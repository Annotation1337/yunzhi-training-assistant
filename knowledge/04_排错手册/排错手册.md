# 排错手册（常见错误与解决方案）

## 1. 服务启动失败

### 报错特征
```
Job for nginx.service failed because the control process exited with error code.
```

### 排查步骤

**第一步：查看服务状态**
```bash
systemctl status nginx
```

**第二步：查看错误日志**
```bash
journalctl -u nginx -n 20
```

**第三步：定位原因**

常见原因及解决方案：

| 原因 | 日志特征 | 解决方案 |
|------|---------|---------|
| 端口被占用 | `bind() to 0.0.0.0:80 failed (Address already in use)` | 换端口或停掉占用服务 |
| 配置错误 | `[emerg] unknown directive` | 检查配置文件语法 |
| 依赖缺失 | `libxxx.so not found` | 安装缺失依赖 |

**检查端口占用**：
```bash
ss -tlnp | grep :80
```

## 2. 端口不通 / 无法远程连接

### 排查步骤
1. 检查安全组是否放通端口
2. 检查防火墙规则
3. 检查服务是否监听正确端口
4. 检查公网 IP 是否绑定

```bash
# 查看监听端口
ss -tlnp

# 检查防火墙
sudo ufw status
```

## 3. 子网可用 IP 不足

### 报错特征
```
Insufficient IP addresses in subnet
```

### 解决方案
1. 检查子网 CIDR 掩码，扩大网段
2. 清理不再使用的实例释放 IP
3. 新建子网迁移资源

## 4. 权限不足

### 报错特征
```
Permission denied
```

### 解决方案
```bash
# 使用 sudo 提权
sudo <命令>

# 检查文件权限
ls -l <文件>

# 修改权限
chmod 755 <文件>
```

## 5. 磁盘空间不足

### 排查
```bash
df -h          # 查看磁盘使用
du -sh /*      # 查看各目录占用
```

### 解决
- 清理日志：`journalctl --vacuum-size=100M`
- 删除无用安装包：`sudo apt clean`
